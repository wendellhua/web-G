## 1. 全局 ID 枚举更新（`schemas/ids.schema.ts`）

- **新增 `StageId`（5 项）**：`stage_1`、`stage_2`、`stage_3`、`stage_4`、`stage_5`
- **新增 `FormId`（5 项，替代 V1 3 角色）**：`form_1_initiate`、`form_2_pulse`、`form_3_phase`、`form_4_astral`、`form_5_void_apex`
- **保留不变**：6 主动武器 `WeaponId`、6 被动核心 `PassiveId`、6 觉醒超武 `EvolutionId`、10 敌怪 `EnemyId`、3 信标 `BeaconKind`、8 天赋 `TalentId`。

## 2. 静态数值配置表设计（`schemas/config.schema.ts`）

### 2.1 全局低起点基础面板（全 5 形态共享，零形态属性偏移）
- `basePlayerMaxHp = 100`
- `basePlayerMoveSpeedPxPerSec = 150`（配合 `warp_engine` 满级 `+30% → 195 px/s`）
- `basePlayerPickupRadiusPx = 100`（配合 `gravity_horizon` 满级 `+80% → 180 px`）
- `tracking_pulse` Lv.1 `cooldownMs = 420 ms`；`runner` 基础移速 `128 px/s < 150 px/s`（Zod 强制校验）。

### 2.2 五大阶段与五形态严格绑定配置表（`StageConfig` & `FormConfig`）

| `stageId` | 关卡号区间 | 累计通关解锁 | 绑定 `formId` | 槽位上限 | 初始主武等级 | 时长上限 (`Sec`) | Boss 登场时刻 (`Sec`) | 开放普通敌怪池 | 祭坛 / 精英 / 无尽 |
| :--- | :---: | :---: | :--- | :---: | :---: | :---: | :--- | :--- | :--- |
| `stage_1` | `1 ~ 3` | `0` | `form_1_initiate` | `2 + 1` | `Lv.1` | `180`（3m） | `[120]`（1 只） | `swarm`, `runner` | 否 / 否 / 否 |
| `stage_2` | `4 ~ 8` | `3` | `form_2_pulse` | `2 + 2` | `Lv.2` | `300`（5m） | `[120, 240]`（2 只） | `+ spitter, tank` | 是 / 是 / 否 |
| `stage_3` | `9 ~ 16` | `8` | `form_3_phase` | `3 + 2` | `Lv.3` | `420`（7m） | `[240, 360]`（2 只） | `+ bomber` | 是 / 是 / 否 |
| `stage_4` | `17 ~ 25` | `16` | `form_4_astral` | `3 + 3` | `Lv.4` | `540`（9m） | `[240, 360, 480]`（3 只） | `+ splitter` | 是 / 是 / 否 |
| `stage_5` | `26+` | `25` | `form_5_void_apex` | `4 + 4` | `Lv.5` | `660`（11m） | `[240, 360, 480, 600]`（4 只） | 全普通怪 | 是 / 是 / **是** |

- **关内递进微调**：设某关在当前阶段内的局部序号为 `subIndex = currentLevel - stage.minLevelNumber`（从 0 起），敌怪血量与刷怪密度在阶段基线之上额外乘以 `1 + subIndex * stage.subLevelHpStepMult`（封顶防溢出），确保第 1→2→3 关亦有清晰挑战递进。
- **跨表 Zod 强校验（`superRefine`）**：强制校验 5 个阶段与 5 个形态一对一绑定、槽位精确对应 `[2+1, 2+2, 3+2, 3+3, 4+4]`、起始主武等级精确对应 `[1, 2, 3, 4, 5]`、单局时长精确对应 `[180, 300, 420, 540, 660]`、Boss 数量精确对应 `[1, 2, 2, 3, 4]` 且全部登场时间 `< durationLimitSec`。

## 3. 运行时状态扩展（`schemas/runtime.schema.ts`）

- `PlayerRuntimeState` 将 `characterId` 替换为 `formId: FormId`，并新增只读上下文：`currentLevel`、`stageId`、`maxActiveSlots`、`maxPassiveSlots`。
- 运行时新增多 Boss 进度追踪字段：`durationLimitSec`、`bossesTotal`、`bossesSpawned`、`bossesKilled`、`defeatReason: 'hp_zero' | 'timeout' | null`。

## 4. 本地持久化 Schema V2 与 V1→V2 自动迁移（`schemas/save.schema.ts`）

- 维持存储键 `void_runner_save_v1`，将 `CURRENT_SAVE_SCHEMA_VERSION` 升级为 **`2`**（`SaveDataV2Schema`）：
  ```ts
  career: {
    currentLevel: number;       // >= 1，默认 1，严格递增
    clearedLevelsCount: number; // >= 0，默认 0，严格递增
    currentStageId: StageId;    // 默认 'stage_1'
    unlockedFormId: FormId;     // 默认 'form_1_initiate'
  }
  ```
- **无痛迁移（`v1 → v2`）**：读取旧版 `schemaVersion === 1` 存档时自动保留玩家已有虚空晶体、天赋等级、战绩、超武图鉴与护眼设置，并按 `totalVictories` 初始化 `career` 进度（若旧版购买角色消耗过晶体不影响正常游戏）。
- **完整重置生涯（`resetCareer`）**：用户二次确认后调用，生成全新的 `createDefaultSaveData()`（仅可保留用户音频/护眼设置或完全重置），将关卡进度、形态、天赋、晶体、战绩全部清零回第 1 关。
