## 阶段 1：游戏概念与核心玩法规格梳理（需求探索）

> **目标产物**：经过多轮澄清定稿后的 `docs/01.游戏设计规格书(GDD-Lite).md`  
> **推进方式**：先发送下方首轮提示词，与 AI 逐轮对话澄清，直到无阻塞性问题后再下达"整理并输出定稿文档"指令。

```text
请先完整阅读项目根目录的 CLAUDE.md，并严格遵循其中的【第 1 节：阶段 1 规则】。

你现在是一名资深网页游戏制作人兼系统策划，擅长动作肉鸽（Survivors-like / Bullet Heaven）类纯前端页游的玩法设计与 MVP 范围把控。

【项目背景】
我准备开发一款纯前端 PC 端网页游戏《黑潮突围（VOID RUNNER）》（16:9 横屏，键鼠操作为主，中型精品独立页游体量）。
核心定位：经典无限大地图生存割草 × 动态地图事件祭坛 × 武器/被动超武合成 × 局外永久天赋树与角色解锁。

【初步设想的功能与体验清单】
1. 核心局内玩法：玩家操控角色在无限延伸的暗黑深空荧光地图中生存割草；支持鼠标瞄准与自动瞄准切换；击杀源源不断的黑潮敌群掉落经验宝石并磁吸回收；升级触发肉鸽三选一（新武器 / 武器升级 / 被动核心）；特定「满级主动武器 + 对应被动核心」可进化为质变超武。
2. 地图探索驱动：无限地图中会动态刷新地图事件（如高危祭坛、精英包围圈、能量补给信标、磁铁/核爆道具），引导玩家持续移动突围而非原地挂机。
3. 局内节奏与胜负：完整单局时长约 10~12 分钟，包含多阶段刷怪导演节奏、中期精英潮与最终 Boss 战；击败最终 Boss 通关，生命归零则结算失败。
4. 局外循环与存档：单局结算获得虚空晶体，用于局外永久天赋树强化、解锁不同初始特性角色、查看历史战绩；全部数据通过浏览器本地持久化保存。
5. 视觉与音频：高辨识度程序化几何/荧光视觉风格（不依赖重型外部美术包）+ 清脆有打击感的 Web Audio 音效反馈。

以上都只是初步设想，大量玩法细节、数值边界与 MVP 范围尚未确定。

【本轮任务边界（重要）】
- 不要直接编写完整规格文档；
- 不要开始写任何代码，也不要讨论具体代码实现细节；
- 不要臆造我没说过的玩法系统，不要替我做决定；
- 你的核心职责是"把玩法边界和架构决策点问清楚"，而不是"一口气把文档写满"。

请先帮我完成以下 4 件事：
1. 分析《黑潮突围》的核心目标玩家诉求与 30 秒核心爽点循环（Core Loop）。
2. 梳理当前已明确的设想，以及仍然模糊、缺失或容易引发范围爆炸的部分。
3. 按游戏系统模块（局内操作与战斗、武器与超武构筑、地图事件与刷怪节奏、局外成长与存档、视听与 UI）列出待确认点。
4. 从这些问题中，优先提出第 1 轮最影响核心玩法与底层架构的 3 个问题（附候选方案、倾向建议与"为什么问"），并在末尾输出【当前规格快照】。

现在，请开始第一轮。
```

## 阶段 2：核心玩法灰盒原型验证（Greybox Playable Prototype）

> **目标产物**：`prototype/` 独立可玩灰盒原型 + `docs/02.灰盒原型验证结论.md`  
> **核心目的**：用最低成本验证"无限卷轴走位 + 瞄准射击 + 怪潮追击/碰撞 + 经验磁吸 + 打击手感"是否真的好玩顺手。

```text
请先阅读 CLAUDE.md（重点遵循【第 2 节：阶段 2 规则】）与已确认的 docs/01.游戏设计规格书(GDD-Lite).md。

现在进入阶段 2：核心玩法灰盒原型验证。
请在 prototype/ 目录下生成一个独立、零构建依赖（或极简静态即可直接在浏览器打开运行）的可玩灰盒原型（例如 prototype/index.html），用于验证《黑潮突围》最核心的 30~60 秒生存割草循环与操作手感。

本阶段必须实现：
1. 无限延伸视差网格地面 + 相机平滑跟随。
2. 玩家几何角色（WASD 移动 + 鼠标手动瞄准/自动瞄准切换 + 冲刺/核心交互，按 GDD 确认项实现）。
3. 至少 2 种代表性几何敌怪的波次生成、追击与基础分离（防完全叠成一个点）、碰撞扣血与无敌帧。
4. 至少 1~2 种基础武器射击/范围攻击、受击闪白、击退、击杀掉落经验宝石与磁吸拾取、简易升级弹窗（临时 3 选 1 数值强化）。
5. 屏幕右上角内置可折叠的【实时调参面板（Debug Tuning Panel）】，支持实时调整：玩家移速、敌怪移速、刷怪速率、射速、击退力度、吸取半径、同屏怪数上限，以及实时显示 FPS 与当前实体数量。

严格边界：
- 仅使用纯几何图形与基础 Web Audio 提示音（可选），严禁投入精力做复杂美术、主菜单、本地存档、永久天赋树、完整超武库与多阶段 Boss。
- 代码明确归属 prototype/ 一次性验证目录，不作为后续正式生产代码基座。

完成后，请告诉我如何打开试玩，并列出一份【手感体验自检清单】引导我试玩反馈。
```
